# Weather in the top bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A weather pill at the end of the top bar ("☀ 98° · Tempe") for wherever the Mac is, with a glass hold card for today, fed by Open-Meteo and the Mac's Location Services.

**Architecture:** The Reminders helper gets a sixth mode, `--location` (disclaimed, JSON lines), that reports Location access, returns a one-off position and looks up a place name. A main-process `services/weather/` service starts that helper only while weather is on, reads Open-Meteo every 15 minutes only while the pill can be seen (as Next bus does), and pushes a `WeatherState` over IPC. The renderer draws the pill (part of `PillRow`'s hold morph) and the card (on `PeekCard`), converting °C to the user's unit at display.

**Tech Stack:** Electron + TypeScript strict + React, Vitest, plain CSS; Swift (CoreLocation, MapKit) in `native/mac-reminders`.

**Spec:** `docs/superpowers/specs/2026-10-27-weather-design.md`

## Global Constraints

- CLAUDE.md is binding: no `any`; IPC channels and payload types only in `src/main/ipc.ts`; the renderer never touches the network or Node; every source behind an interface with a mock; `process.platform` read only in `src/main/platform.ts` (`isMac`); comments say why.
- Only host: `https://api.open-meteo.com/v1/forecast`, through `fetchJson` in `src/main/services/http.ts`. Position rounded to 2 decimals. Always metric (no unit parameter).
- Never log, persist or send the position or the place name anywhere else. No `console.*` with either.
- Poll every 900 s while visible; backoff `[60, 120, 300]` s then 900; a reading shows for 3600 s after it was read; clicks retry at most every 10 s.
- °F default, `weather.unit: 'f' | 'c'`; whole degrees; `widgets.weather` defaults to `false`.
- Credit text exactly "Weather: Open-Meteo".
- Usage text exactly: "Focus Screen shows the weather where you are. Only a rounded position goes to the weather service."
- After each task: `npm run typecheck`, `npm run lint`, `npm test` pass; commit on this branch with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push.
- No looping animation; no finite CSS keyframes inside cards.

## Review Focus

1. **Weather turned off while a read is in flight**: the late answer must not bring a reading or place back (generation counter), and the helper must be stopped. → Task 5 test `drops a read that finishes after weather is turned off`.
2. **Location Services off for the whole Mac, or access revoked while running**: the pill must switch to its fix-it wording, not keep an old temperature forever. → Task 5 tests `servicesOff from locate shows access off` and `access turning denied clears the reading`.
3. **Open-Meteo answers with missing or mismatched arrays** (a field absent, hourly arrays of different lengths, NaN): treat as a failed read, keep the last good reading. → Task 3 tests `parseForecast rejects …`.
4. **The Mac moves less than 1 km, or the place lookup fails**: no second lookup for small moves; a failed lookup after a big move shows no place (never the old town, never coordinates) and is tried again on the next read. → Task 5 tests `looks the place up again only after 1 km` and `a failed place lookup shows no place and retries`.
5. **The hour turns between reads**: the card's six hours must start at the next whole hour from the renderer's clock, not from the read time. → Task 7 test `nextHours starts after now, not after readAt`.
